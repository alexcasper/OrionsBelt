# NPU operator-coverage probes

Minimal ONNX graphs, one Gated DeltaNet operator family each, for auditing what the CIX
NOE Compiler can and cannot compile. Generated by [`scripts/npu_op_probe.py`](../../scripts/npu_op_probe.py).

Beads: authored under `ob-t3b.2`, consumed by the audit `ob-t3b.1`.

Regenerate with:

```bash
python3 scripts/npu_op_probe.py --out artifacts/npu_op_probe
```

## Why these are hand-authored

`torch.onnx.export` fuses, decomposes, and renames operators on the way out, so a rejected
export tells you *a model* failed, not *which primitive* caused it. Each graph here holds one
operator family and nothing else, so a `cixbuild` failure is attributable to exactly one thing.
That attribution is the entire value of the audit.

## The probes

| Probe | Ops | What it tests |
|---|---|---|
| `01_causal_conv1d` | Conv | GDN's short convolution as depthwise Conv1D, kernel 4, **left-only padding**. Tests depthwise grouping *and* asymmetric pads — some compilers accept only symmetric padding. |
| `02_decay_cumprod` | Log, CumSum, Exp | Gated decay. **ONNX has no CumProd**, so `exp(cumsum(log(a)))` is the only standard route. CumSum is scan-shaped and a plausible gap on matmul-oriented silicon. |
| `03_delta_rule_update` | MatMul, Sub, Add, Transpose | One delta-rule step `S ← (I − k kᵀ) S + k vᵀ`. Pure dense linear algebra — the probe most likely to pass. If it fails, the NPU cannot host GDN layers at all. |
| `04_gate_chain` | Sigmoid, Softplus, Neg, Exp, Mul | Elementwise gating. Expected to pass; included so a failure isolates cheaply. |
| `05_scan_recurrence` | **Scan**, Mul, Add, Identity | **The crux.** Chunk-to-chunk recurrence via ONNX control flow. NPU compilers built for feed-forward networks frequently support no control flow at all. |
| `06_loop_recurrence` | **Loop**, Mul, Identity | Same recurrence via `Loop` instead of `Scan` — compilers sometimes accept one form and not the other. |

Shapes come from Qwen3.5's verified linear-attention config (`docs/CLAIM_VERIFICATION.md` §2.3):
`linear_conv_kernel_dim=4`, `linear_key_head_dim=128`, `linear_value_head_dim=128`,
`linear_num_key_heads=16`. Sizes are small on purpose — coverage is a property of the operator
set, not of tensor size. **If a probe passes here but fails at production shapes, that is itself
a finding worth recording.**

## These graphs are known-good

Before drawing any conclusion from a `cixbuild` rejection, note that all six graphs have been
verified locally, so a failure is a NOE coverage gap rather than a malformed input:

- all six pass `onnx.checker.check_model(..., full_check=True)`
- all six execute under `onnxruntime` 1.28 (CPUExecutionProvider) with finite outputs
- `01_causal_conv1d` is verified **genuinely causal**: perturbing the final timestep leaves every
  earlier output bit-identical (max delta 0.0) while changing the last one

## Running the audit once the SDK is installed

In the NOE SDK's Python 3.10 environment (`cixbuild -v` should work first):

```bash
for f in artifacts/npu_op_probe/*.onnx; do
  echo "=== $f ==="
  cixbuild "$f" 2>&1 | tee "artifacts/npu_op_probe/$(basename "$f" .onnx).cixbuild.log"
done
```

Consult the SDK's own docs for the exact invocation — it may want a build config rather than a
bare path. Adjust, but keep one log per probe.

## Recording results

For each probe record one of: **compiles** / **compiles with fallback** (note which ops fell back
to CPU — a silent fallback is the most important case to catch, since it looks like success and
performs like failure) / **rejected** (quote the error). Then write the table into
`docs/FINDINGS.md`.

A negative result is the finding, not a failure. "The NOE Compiler has no kernel for a gated
recurrent scan" is precisely the empirical justification the mapping ADR needs for routing the
sequential scan to GPU/CPU while keeping dense per-chunk math on the NPU. It is also the most
reusable thing this project can hand to anyone else porting a GDN-class model to this silicon.
